Data · Transliteration

  
Cyrillic → Latin

  

    

    

      
■ three letters become two characters: љ→lj, њ→nj, џ→dž

      
■ letters with diacritics stay a single character

      
Cyrillic → Latin is deterministic. The reverse is not: injekcija (n+j), nadživjeti (d+ž).

      
For a char-level model this means: “lj” and “nj” are two tokens, so the model has to learn them as a pair.

    

  

  

    
[1:00 | total 7:30]

    
Why Latin script? The audience reads it more easily on slides, and the model is exactly the same. We could have kept Cyrillic too: char-level doesn't care.

    
Fun fact: Cyrillic is phonetically cleaner for the model (one sound = one character). In Latin script “lj/nj/dž” are two tokens, so the sequence is slightly longer.

Language modeling

  
The task: predict the next character

  

    
    

      
context     target
N         → e
Ne        → k
Nek       → a
…
Neka·bud  → e

      
    
        
  • Input x and target y are the same text, shifted by one
    • 
        
  • One chunk of length block_size = block_size examples at once (every position is a separate example)
    • 
        
  • The model never sees the future: at position t it knows only x≤t
    • 
      

    

  

  

    
[2:00 | total 12:00]

    
This is the whole “trick” of GPT: self-supervised learning, where the labels are the text itself shifted by one.

    
On the diagram block_size = 8 for clarity; ours is 256. From one chunk of 8 we get 8 examples: from a context of length 1 up to a context of length 8. That is why the model can also generate from a short prompt.

  







  
Language modeling · Batch and loss

  
Batch, cross-entropy and the initial loss

  

    
n = int(0.9 * len(data))
train_data, val_data = data[:n], data[n:]   # 90% / 10%

def get_batch(split):
    d = train_data if split == "train" else val_data
    ix = torch.randint(len(d) - block_size, (batch_size,))  # random starts
    x = torch.stack([d[i : i + block_size] for i in ix])
    y = torch.stack([d[i + 1 : i + 1 + block_size] for i in ix])  # shifted by 1
    return x, y  # both (B, T) = (64, 256)

    

      

      

        
Sanity check at the start

        
An untrained model ≈ uniform distribution, , so

B = 64 chunks, T = 256 positions: 16,384 predictions per step. Cross-entropy is the average negative log-probability of the correct next character.

    
This is the first number we look at in the training log: if V is around 80, we expect ~4.4 at step 0. That is why the GPT-2 init with std 0.02 matters: the logits are close to zero, so the distribution is almost uniform.

Self-attention · 1/6

  
The idea: tokens communicate, but only with the past

  

    
    

      
The token at position t gathers information from positions 1…t. The future is off-limits, because that is what we are predicting.

      
The simplest communication: the average of all previous vectors. It loses the order, but it's a start.

    

  

  

    
[1:30 | total 16:30]

    
Following Karpathy: each token is a vector of dimension C. We want the token “b” to get information from “N, e, k, a, space”. The simplest way: take the average of their vectors. That is a “bag of words”, but it is enough to introduce the matrix trick.

  







  
Self-attention · 2/6

  
The trick: averaging the past = matrix multiplication

  

    
    

      
tril = torch.tril(torch.ones(T, T))
wei = tril / tril.sum(1, keepdim=True)  # rows sum to 1
out = wei @ x  # (T, T) @ (B, T, C) -> (B, T, C)

      
# the same, but via softmax:
wei = torch.zeros(T, T)    # later: learned affinities!
wei = wei.masked_fill(tril == 0, float("-inf"))
wei = F.softmax(wei, dim=-1)

    

  

  

    
[2:30 | total 19:00]

    
A lower-triangular matrix of ones, normalized by rows: row t has 1/t in its first t entries. Multiply it by x and you get the average of the past for all positions at once, in a single matmul.

    
The right-hand version is the key one: we start from zeros, put -inf where the future is, and softmax turns -inf into 0. The result is the same, but now we can replace the zeros with learned affinities: how interesting token j is to token t. That is self-attention.

  







  
Self-attention · 3/6

  
Query, Key, Value

  

    

    

      
query
“What am I looking for?” e.g. a vowel before me

      
key
“What do I offer?” e.g. I am a space

      
value
“What I pass along” if someone picks me

      
Affinity = . All three are just nn.Linear over the same x.

    

  

  

    
[2:30 | total 21:30]

    
Each token emits three vectors. Query: what I am interested in. Key: what I contain. When one token's query matches another's key (a large dot product), the affinity is high.

    
On the diagram: the token “b” asks, the others answer with their keys; the softmax of the affinities gives the weights, and the output is a weighted sum of the value vectors. The value is separate from the key: what you find me by does not have to be what I hand over to you.

With  the std is 8 → softmax becomes one-hot and gradients vanish. Dividing by  brings the variance back to 1.

      

      

    

  

  

    
[2:00 | total 23:30]

    
The formula from “Attention Is All You Need”. The only new detail compared to the previous slide is the scaling.

    
Intuition from the diagram: the same affinities, just 8 times larger. Softmax is exponential, so large numbers give an almost one-hot output: each token would listen to only one other token, and the gradient through the softmax would be almost zero. That is why it matters that the softmax is “diffuse” at init.

  







  
Self-attention · 5/6

  
Causal mask: -inf where the future is

  

    
    

      
att = att.masked_fill(self.mask[:, :, :T, :T] == 0, float("-inf"))
att = F.softmax(att, dim=-1)  # exp(-inf) = 0

      
No mask = encoder (BERT). With the mask = decoder (GPT). Everything else is the same.

    

  

  

    
[1:00 | total 24:30]

    
The affinity matrix is T×T: the row is the query (who is asking), the column is the key (who is being asked). The upper triangle is the future, so we put -inf there. After the softmax each row sums to 1 and the future has weight 0.

    
The mask is registered as a buffer (torch.tril); it is not a parameter and is not learned.

  







  
Self-attention · 6/6

  
Multi-head: independent communication channels

  

    
    

      
6 heads × 64 = 384: the same compute as one big head, but 6 different “questions” in parallel.

      
E.g. one head tracks the rhythm of the verse, another the rhyme, a third gender and case agreement (in an ideal world).

    

  

  

    
[1:30 | total 26:00]

    
A single Linear (c_attn) produces q, k, v for all heads at once; reshape to (B, nh, T, hs) and attention is computed for all heads in parallel, as a batch dimension. At the end we merge the heads back into C and pass the result through c_proj.

    
The remark on interpreting heads is speculative: a nice story, but in practice heads rarely have such clean roles.

  







  
Transformer

  
Transformer block: communication + computation

  

    

    
    
      
  • Attention: tokens exchange information
    • 
      
  • MLP (4× wider, GELU): each token “thinks” about what it gathered, independently
    • 
      
  • Residual connections: x = x + f(x), a highway for the gradient from output to input
    • 
      
  • Pre-LayerNorm: normalization before the sublayer (GPT-2), more stable training than the original post-LN
    • 
    

  

  

    
[2:00 | total 28:00]

    
Block = two sublayers, each of the form x + f(LN(x)). The residual stream is the “main highway” through the network: each block only adds a small correction. At init the blocks are almost the identity, so deep networks train easily. (That is also why we scale the c_proj weights by 1/sqrt(2·n_layer).)

    
The 2017 original has the LN after the addition; GPT-2 moved it in front, with an extra LN at the end of the network.

  







  
Transformer · GPT

  
The full GPT in one picture

  

    
    

      
Weight tying: wte and lm_head share the same V×C matrix. Input and output “speak the same language”.

      
For us it saves only ~30K parameters; for GPT-2 (V = 50,257, C = 768) a full 38.6M.

    

  

  

    
[2:00 | total 30:00]

    
The token embedding says WHAT the token is, the positional embedding says WHERE it is. We add them (we do not concatenate). Positions are learned, not sinusoidal. Then N blocks, a final LayerNorm and lm_head, which returns logits of size V for every position.

    
Weight tying: the same matrix serves for input and output. Intuition: characters that are similar as inputs should be similar as predictions too.

  







  
Code · model.py

  
CausalSelfAttention.forward

  

    
def forward(self, x):
    B, T, C = x.size()  # batch, sequence length, embedding dimension
    # a single Linear produces q, k, v for all heads at once
    q, k, v = self.c_attn(x).split(C, dim=2)
    # split into heads: (B, T, C) -> (B, nh, T, hs)
    q = q.view(B, T, self.n_head, C // self.n_head).transpose(1, 2)
    k = k.view(B, T, self.n_head, C // self.n_head).transpose(1, 2)
    v = v.view(B, T, self.n_head, C // self.n_head).transpose(1, 2)

    # attention: softmax(q @ k^T / sqrt(d)) @ v
    att = (q @ k.transpose(-2, -1)) * (1.0 / math.sqrt(k.size(-1)))
    att = att.masked_fill(self.mask[:, :, :T, :T] == 0, float("-inf"))
    att = F.softmax(att, dim=-1)
    att = self.attn_dropout(att)
    y = att @ v  # (B, nh, T, T) @ (B, nh, T, hs) -> (B, nh, T, hs)

    # merge the heads back: (B, nh, T, hs) -> (B, T, C)
    y = y.transpose(1, 2).contiguous().view(B, T, C)
    return self.resid_dropout(self.c_proj(y))

Code · model.py

  
Block and MLP

  

    
class MLP(nn.Module):
    def forward(self, x):
        # expand 4x -> GELU -> back to n_embd
        return self.dropout(self.c_proj(self.gelu(self.c_fc(x))))


class Block(nn.Module):
    def __init__(self, config):
        super().__init__()
        self.ln_1 = nn.LayerNorm(config.n_embd, bias=config.bias)
        self.attn = CausalSelfAttention(config)
        self.ln_2 = nn.LayerNorm(config.n_embd, bias=config.bias)
        self.mlp = MLP(config)

    def forward(self, x):
        # pre-LayerNorm + residual connections
        x = x + self.attn(self.ln_1(x))  # tokens "communicate"
        x = x + self.mlp(self.ln_2(x))   # each token "thinks"
        return x

Code · model.py

  
GPT: embeddings, blocks, head

  

    
self.transformer = nn.ModuleDict(dict(
    wte=nn.Embedding(config.vocab_size, config.n_embd),  # token embedding
    wpe=nn.Embedding(config.block_size, config.n_embd),  # position embedding
    drop=nn.Dropout(config.dropout),
    h=nn.ModuleList([Block(config) for _ in range(config.n_layer)]),
    ln_f=nn.LayerNorm(config.n_embd, bias=config.bias),
))
self.lm_head = nn.Linear(config.n_embd, config.vocab_size, bias=False)
self.transformer.wte.weight = self.lm_head.weight  # weight tying: shared matrix

def forward(self, idx, targets=None):
    B, T = idx.size()
    pos = torch.arange(T, device=idx.device)
    x = self.transformer.wte(idx) + self.transformer.wpe(pos)  # (B, T, C)
    x = self.transformer.drop(x)
    for block in self.transformer.h:
        x = block(x)
    x = self.transformer.ln_f(x)
    logits = self.lm_head(x)  # (B, T, vocab_size)
    loss = None
    if targets is not None:
        loss = F.cross_entropy(logits.view(-1, logits.size(-1)), targets.view(-1))
    return logits, loss

Code · model.py

  
generate: one character per step

  

    
@torch.no_grad()
def generate(self, idx, max_new_tokens, temperature=1.0, top_k=None):
    for _ in range(max_new_tokens):
        # crop the context to the last block_size tokens
        idx_cond = idx[:, -self.config.block_size :]
        logits, _ = self(idx_cond)
        logits = logits[:, -1, :] / temperature  # last position only
        if top_k is not None:
            v, _ = torch.topk(logits, min(top_k, logits.size(-1)))
            logits[logits < v[:, [-1]]] = -float("inf")
        probs = F.softmax(logits, dim=-1)
        idx_next = torch.multinomial(probs, num_samples=1)  # sample
        idx = torch.cat((idx, idx_next), dim=1)
    return idx

    
    
      
  • Autoregressive: the output becomes part of the input
    • 
      
  • The context is cropped to block_size, because wpe only knows 256 positions
    • 
      
  • multinomial, not argmax: otherwise the model quickly gets stuck in a loop
    • 
      
  • No KV cache: we recompute everything (for 10M parameters, fast enough)
    •

Generation is a plain loop. We compute logits for all positions but use only the last one. Temperature and top-k come up in a few minutes, after training.

The training loop

  

    
optimizer = torch.optim.AdamW(groups, lr=1e-3, betas=(0.9, 0.99))
model = torch.compile(model)
ctx = torch.autocast("cuda", dtype=torch.bfloat16)

for it in range(max_iters + 1):
    lr = get_lr(it)  # warmup + cosine
    for g in optimizer.param_groups:
        g["lr"] = lr

    x, y = get_batch("train")
    with ctx:  # forward in bf16
        logits, loss = model(x, y)
    optimizer.zero_grad(set_to_none=True)
    loss.backward()
    torch.nn.utils.clip_grad_norm_(model.parameters(), grad_clip)
    optimizer.step()

    
    
      
  • AdamW: weight decay only on 2D tensors (matrices, embeddings), not on LayerNorm
    • 
      
  • bf16 autocast: ~2× faster, same exponent range as fp32, so no GradScaler needed
    • 
      
  • torch.compile: fuses operations into kernels; we pay once at the start
    • 
      
  • Grad clipping to norm 1.0: a fuse against rare huge gradients
    •

Training · Learning rate

  
Learning rate: warmup + cosine decay

  

    

    

      
def get_lr(it):
    if it < warmup_iters:  # linear warmup
        return learning_rate * (it + 1) / warmup_iters
    ratio = (it - warmup_iters) / (max_iters - warmup_iters)
    coeff = 0.5 * (1.0 + math.cos(math.pi * ratio))
    return min_lr + coeff * (learning_rate - min_lr)

      
    
        
  • Warmup: Adam's moment estimates are unreliable early on, so we start slowly
    • 
        
  • Cosine: big steps while we are far away, fine ones at the end
    •

    • 
      
  • Remedies: dropout 0.3, weight decay, a smaller model, shorter training
    • 
      
  • We keep only the checkpoint with the best val loss
